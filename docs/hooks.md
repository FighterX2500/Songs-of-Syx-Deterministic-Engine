# Hooks into game code

Every change the engine makes to the game's own code, with the reason it exists. The points come from the mod's [hook map](https://github.com/FighterX2500/SOSGSGMP/blob/main/docs/archive/hook-surface.md) (hooks B7–B11 and B15; B12–B14 need no game change) and the SOS-23 city fixes. AGENTS.md "Patches to Game Code" says how a hook is written. ADR 0005, cited throughout, is [SOSGSGMP's](https://github.com/FighterX2500/SOSGSGMP/blob/main/docs/decisions/0005-world-lockstep-and-city-world-link.md).

Most hooks call `sosdet.Hooks`, `sosdet.Cosmetic`, `sosdet.game.AiHooks` or a class in `sosdet.game.cmd`; some change the game's code and call nothing. Each is marked `SOSDET` in the game source.

With no engine session a hook gives the game's own behaviour. The known exceptions, which apply in plain single-player too:
- the fixed tables in `50-fixed-tables`, filled at class load (see that row);
- the path heap in `36-path-heap`: the same paths, faster;
- `MainProcess.main` calls `GameBuild.check` (`99-game-build`), which stops the game on any build but 71.44;
- two game fixes: `WDivStored`'s load clears its stats totals (`14-report-reads`), and a held `GSliderInt` button calls `inc` only for a non-zero amount (`96-cmd-employment`);
- `ResolverPlayer.Manual.afterBattle` counts each side through `sosdetCount` (`15-humans`), so single-player captive counts differ slightly from vanilla;
- a war declared on an NPC that broke its treaties with the player costs no betrayal (`14-report-reads`, owner 2026-11-18, SOS-227; see that row);
- every game holds 15 spare Players, and every save extra sections: `SOSDET_HUMANS`, `SOSDET_CITY_DIVS`, `SOSDET_RELATIONS`, `SOSDET_EVENTS`, `SOSDET_DEALS`, `SOSDET_TARIFFS`, `SOSDET_SIEGES`, `SOSDET_TRADED`, `SOSDET_PASSED` (SOS-140), `SOSDET_CARVES` (SOS-186), `SOSDET_FROZEN` (SOS-193), `SOSDET_BREAKS` (SOS-227), `SOSDET_STATIONS` (SOS-233), `SOSDET_TITLES` (SOSGSGMP spec §5 Titles) and `SOSDET_STATIONED_DIVS` (SOS-234, the city's only, in the save's first list so it loads before the people) (`GameHumans`, from the `FACTIONS` constructor). Every one but `SOSDET_HUMANS` and `SOSDET_STATIONED_DIVS` is in the world save too (`GameWorldLoad.KEYS`); `GameHumans` refuses to start with one that isn't (SOS-137).

## Shared reasons

Rows that share a reason name it in italics:

- *Private*: the code is a private or package-private member, an anonymous class, a static initializer or a local; reflection can't change what a method does.
- *Command* (ADR 0002, [commands.md](commands.md)): a player's UI action changed the simulation at once on one PC; in a session it is a command applied at its step on every PC, hooked at the setter or, when that is generic, hot, menu-unsafe or also run by the simulation, at the UI call site.
- *Report read* (ADR 0005 §2): in the world part a read of the live city reads that human's city report (taken every 30 steps, applied 30 steps later); only the read itself can change.
- *Report input* (ADR 0005 §2): a city-part change to the world travels in the city's next report, and the world part applies it.
- *Transaction* (ADR 0005 §3): a world-part change to the city is applied in the step's city tail.
- *First caller*: whoever asks first (the UI, the city part, the host's general) fills or writes a cache, so PCs filled it differently; in a session only the step, or only the world part, writes it.
- *One player* (ADR 0004): the game treats only `FACTIONS.player()` as the player; each site now treats every human as vanilla's player, usually with that human current, and with one human gives vanilla's result.
- *Cosmetic*: a visual or audio draw in the step, made on some PCs only; only the call site knows, so it moves to the cosmetic stream.
